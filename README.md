# ozon-reviews-parser

CLI-утилита для сбора отзывов о товарах [Ozon](https://www.ozon.ru) в JSON-файлы.
Один товар — один файл `output/{product_id}.json`. Задумана как источник данных для анализа отзывов человеком или ИИ.

## Возможности

- Товар задаётся тремя способами: короткая ссылка «Поделиться» (`ozon.ru/t/...`), полная ссылка карточки (с любыми параметрами) или артикул из поиска (`1234567890`). Можно передать список в файле.
- Фильтр по актуальности: только отзывы за последний год (период настраивается).
- Фильтр по варианту: по умолчанию — все варианты товара; `--this-variant` — только вариант из ссылки.
- Карточка товара: название, цена (обычная / с Ozon-картой / старая), полные характеристики.
- Подробные поля отзыва: автор, оценка, дата, текст, достоинства, недостатки, лайки/дизлайки, факт покупки, ссылки на фото и видео, вариант.
- Вопросы и ответы: отвеченные вопросы — несколько сотен на товар. По одному ответу на вопрос, см. «Ограничения».
- Обезличивание выгрузки (`--anonymize`) — если файл уходит наружу, в том числе в облачную модель.
- Работает через [Patchright](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright-python) и реальный установленный Chrome, без входа в аккаунт.

## Требования

- Python 3.11+
- Установленный **Google Chrome** (используется реальный браузер, отдельный не скачивается)
- **VPN выключен** — Ozon блокирует VPN/прокси-адреса
- Графическое окружение: окно браузера должно быть видимым, поэтому на сервере без экрана
  утилита не работает

Проверялась на Windows. Код кроссплатформенный (пути к Chrome для macOS и Linux учтены),
но на этих системах вживую не тестировалась.

## Установка

**Windows (PowerShell)**

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e .
```

**macOS / Linux**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

После активации в приглашении терминала появляется `(.venv)`, и команда
`ozon-reviews-parser` доступна напрямую — все примеры ниже написаны для этого случая.
**Активацию нужно повторять в каждом новом окне терминала:** без неё команда не найдётся,
а `python -m ozon` запустится системным Python, где нет зависимостей.

Если активировать не получается (PowerShell может блокировать запуск скриптов политикой
выполнения), то же самое работает полным путём, без активации вообще:

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\ozon-reviews-parser.exe -f urls.txt
```

Проект ставится как пакет, поэтому в активированном окружении запускать можно тремя
равнозначными способами: `ozon-reviews-parser ...`, `python -m ozon ...` или
`python main.py ...`.

## Использование

```bash
# Все варианты, отзывы за год (по умолчанию)
ozon-reviews-parser "<ссылка на товар>"

# По артикулу из поиска Ozon — ссылка не нужна
ozon-reviews-parser 1234567890

# Только вариант из ссылки (когда под карточкой собраны разные товары)
ozon-reviews-parser "<ссылка>" --this-variant

# Список ссылок или артикулов из файла (по одной строке, # — комментарий)
ozon-reviews-parser -f urls.txt

# Самопроверка парсинга: сразу видно, какой блок перестал отдаваться
ozon-reviews-parser "<ссылка>" --doctor

# Без персональных данных — если файл уйдёт в облачную модель или коллеге
ozon-reviews-parser "<ссылка>" --anonymize
```

| Флаг | Назначение |
|---|---|
| `--this-variant` | только вариант из ссылки (по умолчанию — все варианты) |
| `--years N` | период актуальности отзывов в годах (по умолчанию 1) |
| `--max N` | максимум отзывов на товар (по умолчанию 500) |
| `--headless` | без окна браузера (на Ozon обычно блокируется) |
| `--output-dir DIR` | куда писать JSON (по умолчанию `output/`) |
| `--profile-dir DIR` | где хранить профиль браузера (по умолчанию `.profile/`) |
| `--anonymize` | убрать из файла имена авторов и их фото/видео — данные третьих лиц |
| `--fresh-profile` | удалить сохранённый профиль браузера перед запуском (если сессия испортилась) |
| `--doctor` | самопроверка парсинга по переданной ссылке; печатает PASS/WARN/FAIL по секциям |

Окно Chrome по умолчанию видимое — это необходимо: в headless-режиме Ozon обычно показывает страницу проверки.

`Ctrl+C` останавливает мягко: текущий запрос доводится до конца, уже собранное сохраняется,
браузер закрывается штатно. Повторный `Ctrl+C` прерывает сразу.

Ключи — как в реальном файле; значения обобщены.

```json
  "url": "https://www.ozon.ru/product/<slug>-<id>/",
  "product_id": "<id>",
  "name": "Название товара",
  "variant": { "Цвет товара": "чёрный" },
  "price": {
    "price": "2 448 ₽",
    "card_price": "2 240 ₽",
    "original_price": "6 843 ₽",
    "is_available": true
  },
  "stats": {
    "overall": { "avg": 4.8, "total": 5066, "source": "ozon" },
    "collected": { "count": 990, "with_text": 524, "empty": 466 },
    "windows": {
      "30d":  { "count": 96,  "avg": 4.71, "dist": {"1": 4, "2": 1, "3": 4, "4": 12, "5": 75}, "covered": true },
      "90d":  { "count": 288, "avg": 4.66, "dist": {"1": 13, "2": 4, "3": 11, "4": 38, "5": 222}, "covered": true },

    "Артикул": "<id>",

    {
      "author": "Имя П.",
      "text": "Текст вопроса о товаре?",
      "date": "25 июня 2026",
      "answers": [
        { "author": "Магазин", "text": "Текст ответа.", "date": "25 июня 2026", "is_best": false }
      ]
    }
  ],
  "reviews_period_days": 365,
  "reviews_count": 500,
  "reviews": [
    {
      "author": "Имя Ф.",
      "rating": 5,
      "date": "2026-06-16",
      "text": "Текст отзыва.",
      "pros": "достоинства",
      "cons": "недостатки",
      "useful_count": 3,
      "unuseful_count": 0,
      "purchased": true,
      "photos": ["https://cdn1.ozone.ru/<...>.jpg"],
      "videos": [],
      "variant": { "Цвет товара": "чёрный" }
    }
  ]

```

Поле `is_best` у ответа сохранено для совместимости формата и сейчас всегда `false`.

Блок `stats` — сводка оценок (окна: 30/90/180/365 дней):
- `overall` — средняя и общее число отзывов **от Ozon** (истина за всё время; анонимная выборка для этого не годится).
- `collected` / `windows` считаются по **хронологической** выборке (лента «сначала новые»), без доборов сортировками по оценке — иначе средняя была бы занижена, т.к. те сортировки намеренно тянут крайние оценки. Пустые отзывы (с оценкой, но без текста) учитываются.
- `covered: false` — выборка не покрывает всё окно (нет отзывов старше его начала): у популярных товаров хронолента упирается в свежие ~990 отзывов, поэтому дальним окнам доверять нельзя.

Блок `lenses` — срезы той же выборки по признакам отзыва. **Это не поправка к оценке.**
Подмножества смещены вниз по построению: недовольные пишут развёрнутее, а голосуют
чаще за критику. Смысл — в разрыве между `all` и остальными строками, а не в
абсолютном значении; смешивать их с `overall` нельзя, иначе любой товар выглядит плохим.

| срез | что отбирает | на что смотреть |
|---|---|---|
| `all` | вся выборка с оценкой | опора для сравнения |
| `substantive` | текст от 150 символов | развёрнутое мнение вместо «всё ок» |
| `voted` | отзыв отметили полезным | что покупатели считают достойным прочтения |
| `with_media` | есть фото или видео | единого направления нет — смотреть только по своему товару |
| `this_variant` | отзывы о том же варианте, что в ссылке | на карточке смешаны отзывы всех цветов и размеров |

Срез `this_variant` и флаг `--this-variant` сравнивают **описание** варианта (цвет, объём,
размер), а не `itemId`: один и тот же вариант живёт у Ozon под несколькими id — это разные
листинги одного товара. У товара без вариантов срез не выводится: он повторял бы `all`.

Замер на 36 товарах (август 2026):

| срез | ниже опоры `all` | средний разрыв | диапазон |
|---|---|---|---|
| `substantive` | 34 из 36 | −0.34 | −1.09 … +0.05 |
| `voted` | 35 из 36 | −0.54 | −1.48 … +0.05 |
| `with_media` | 16 из 36 | +0.02 | −1.23 … +0.57 |

`substantive` и `voted` уходят вниз почти всегда — это устойчивое свойство выборки, а не
оценка товара. У `with_media` единого направления нет: на одних товарах срез ниже опоры
больше чем на балл, на других примерно настолько же выше. Поэтому постоянный балл за фото
был бы неверен в обе стороны, а как срез он информативен — но читать его нужно по своему
товару, а не по среднему.

Пороги настраиваются в `config.py` (`LENS_MIN_CHARS`, `LENS_MIN_USEFUL`).

Сводка срезов по всем собранным файлам сразу, без сети:

```bash
python scripts/lenses.py
```

## Как это работает

1. Запускается реальный Chrome через Patchright (`channel="chrome"`), без входа в аккаунт.
2. Браузер проходит проверку Ozon; сессия сохраняется в `.profile` для повторных запусков.
3. Из живой сессии берутся заголовки внутреннего API, дальше лента отзывов запрашивается напрямую и листается по курсору — несколькими проходами с разным порядком сортировки, чтобы в выборку попали и свежие отзывы, и крайние оценки.
4. Отзывы фильтруются по дате и варианту (`itemId`), пустые (без текста) пропускаются, сортируются «сначала новые».
5. Цена и характеристики берутся с карточки и страницы `/features/`.
6. Вопросы с ответами собираются постранично: в каждом ответе есть указатель на следующую страницу, по нему и идём, пока страницы не кончатся. Ответы приходят вместе с вопросом.
7. Результат сохраняется в `output/{product_id}.json`.

`scripts/recon.py` — диагностический скрипт: сохраняет сырые ответы Ozon в `captures/` (полезно при поломке парсера после изменений на сайте). Все скрипты в `scripts/` принимают тот же ввод, что и основная команда: ссылку или артикул.

## Структура

```
ozon/
  __main__.py  запуск пакета: python -m ozon
  cli.py       разбор аргументов и запуск (точка входа)
  runner.py    оркестрация: браузер -> сбор -> сохранение
  collector.py сбор одного товара (ReviewCollector)
  api.py       внутренний API Ozon: адреса, fetch, ожидание капчи
  parse.py     разбор JSON-ответов в данные
  stats.py     сводка оценок: временные окна и срезы выборки
  anonymize.py обезличивание выгрузки (--anonymize)
  doctor.py    самопроверка (--doctor)
  models.py    Review и Product
  storage.py   атомарная запись JSON
  browser.py   запуск реального Chrome через Patchright
  urls.py      разбор ввода: ссылка или артикул
  config.py    настройки с объяснением каждого значения
  errors.py    типы ошибок парсера
  interrupt.py мягкая остановка по Ctrl+C
  logging_setup.py  общий файловый лог для всех модулей
scripts/       диагностические скрипты (общая обвязка — _common.py)
tests/         офлайн-тесты и обезличенные реальные ответы Ozon
```

Всё, что зависит от структуры сайта Ozon (пути, имена виджетов, параметры сортировок),
собрано в `ozon/api.py` — при изменениях на стороне Ozon правится он.
Все параметры поведения (паузы, лимиты пагинации, окна статистики, ожидание капчи,
таймзона дат) вынесены в `ozon/config.py` с объяснением, откуда взято каждое значение.
Ссылок на конкретные товары в коде нет — товар всегда задаёт пользователь.

## Персональные данные

Отзывы и вопросы пишут живые люди: в файл попадают имена авторов («Имя Ф.») и ссылки
на их фотографии. Каталоги `output/`, `captures/`, `logs/` и профиль браузера `.profile/`
перечислены в `.gitignore` и в репозиторий не попадают.

Перед тем как отправить выгрузку наружу — в облачную модель, коллеге, в публичный
репозиторий — собирайте с `--anonymize`: имена заменяются на «Автор 1», «Автор 2»
(один человек получает один псевдоним во всех разделах), пользовательские фото и видео
убираются. Оценки, тексты, достоинства и недостатки остаются — для анализа товара нужны
именно они.

Оговорка режима: авторы ответов обезличиваются тоже, поэтому различие «ответил магазин /
ответил покупатель» пропадает. Если оно важно — собирайте без флага и не передавайте файл.

Отдельно про `.profile/`: это настоящий профиль Chrome с cookie-сессией Ozon, он лежит
в каталоге проекта и весит сотни мегабайт. При копировании, архивации или передаче проекта
исключайте его — или задайте другое место флагом `--profile-dir`.

## Тесты

Чистая логика парсинга и фильтрации покрыта офлайн-тестами (`tests/`, pytest) — сеть и браузер не нужны:

```bash
pip install -e ".[dev]"
pytest
```

Точные версии зависимостей зафиксированы в `uv.lock` (`uv sync` воспроизводит окружение).
Проверка зависимостей на известные уязвимости:

```bash
pip-audit
```

Сетевое ядро (`ReviewCollector`) тестами не покрыто — проверяется только живым запуском с выключенным VPN.

## Глубина и лимиты (без аккаунта)

- **Потолок — около 2900 отзывов на товар, и он абсолютный, а не долевой.** У товара
  с 500 отзывами соберётся всё; у товара с сотнями тысяч — те же ~2900, начиная со свежих.
- Отзывы набираются несколькими проходами с разным порядком сортировки: так в выборку
  попадают и свежие отзывы, и крайние оценки, а не только начало ленты. Поэтому добор
  включён по умолчанию.
- Около половины собранного — отзывы с оценкой, но без текста. В файл они не попадают,
  но учитываются в блоке `stats`.
- Вопросов собирается меньше: на проверенных товарах выходило от сотни до четырёхсот.
- Скорость: один товар целиком — около минуты, с лимитом `--max` — секунды.
- На непопулярных товарах данные уходят на несколько лет назад — там имеет смысл
  `--years 2` или `3`.

Замерить глубину на своём товаре: `python scripts/audit.py "<ссылка или артикул>" --all-sorts`.

## Ограничения

- Без аккаунта доступно ~2900 отзывов независимо от того, сколько их у товара — см. «Глубина и лимиты». Вопросов собирается больше: на проверенных товарах выходило 160–400 (берутся только отвеченные).
- **У вопроса собирается один ответ — лучший.** Если ответов несколько, остальные в файл не попадают: они подгружаются отдельно, и поддержка этого ещё не сделана.
- Автоматический сбор нарушает правила использования Ozon. Используйте для личных целей и с разумными паузами.
- Парсер зависит от текущей структуры Ozon — при изменениях на стороне сайта потребуется правка.

## Планы развития

Базовый сбор (текущий `main`) самостоятелен и работает без расширений. Новые возможности добавляются **опционально** — отдельными флагами и зависимостями, чтобы тем, кому нужны только данные по товару, ничего лишнего не требовалось. Каждая возможность разрабатывается в своей ветке.

- **Статистика отзывов** — *реализовано*. Распределение оценок по окнам (30/90/180/365 дней) рядом со средним за всё время от Ozon: видно, как меняется качество со временем (свежие отзывы часто ниже общей оценки). Плюс срезы `lenses` — как выглядит оценка среди развёрнутых отзывов, отмеченных полезными и с фото.
- **Самопроверка парсинга** — *реализовано*. Офлайн-регрессия на реальных ответах Ozon + режим `--doctor`, который сразу показывает, какой блок перестал отдаваться (вместо молчаливого пустого JSON).
- **ИИ-анализ (опционально)** — *в планах*. Вердикт по собранным данным: локальной моделью через Ollama или по API-ключу. Включается флагом, на базовый режим не влияет.
- **Локальный веб-интерфейс** — *в планах*. Вставил ссылку, получил файл, статистику и вердикт, без командной строки (только на своей машине: нужен видимый Chrome и выключенный VPN).

## Если Ozon начинает блокировать

Убедитесь, что окно видимое (не `--headless`) и VPN выключен. Более незаметный фолбэк без переписывания логики — [Camoufox](https://github.com/daijro/camoufox) (управляется тем же Playwright API).
